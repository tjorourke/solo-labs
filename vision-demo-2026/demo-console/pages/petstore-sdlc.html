Agent SDLC

A product idea becomes a reviewed, deployed feature.

Two kagent agents, one GitHub issue as the handoff between them, and a human approval gate before anything reaches prod. Every step below is real: a real repo (tjorourke/demo-petstore), a real commit, a real deploy on kind-mesh1.

•
How the pieces talk

Not agent-to-agent. Agent-to-GitHub, twice.

pm-bot and dev-bot never call each other. Each speaks A2A to kagent, the same protocol every agent on this cluster uses for chat, and each reaches GitHub through the same MCP waypoint the rest of this demo already trusts. The GitHub issue, its body and its label, is the only interface between them: a real, auditable handoff a person can read at any point, not a hidden message between two LLMs.

Review staging, then approve or deny
