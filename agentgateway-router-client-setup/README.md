# Running editors and agents through a semantic router

Sample configuration for the how-to at
<https://mastertheagent.com/solo/agentgateway-router-client-setup/>.

This is the intake hop: the gateway clients reach first, in front of whatever gateway fronts
the router. It normalises the model name, filters the tool shapes the backends reject, and
converts Anthropic Messages to chat completions so the router only ever reads one wire format.

`yaml/` is the Enterprise CRDs, `yaml-oss/` the same objects on the OSS CRDs, generated by the
group and kind swap the page describes.

```bash
kubectl apply -f yaml/       # or yaml-oss/
```

| File | What it is |
| --- | --- |
| `00-intake-gateway.yaml` | The front door, a Gateway of its own because a transformation runs after an external processor on the same hop |
| `10-intake-policy.yaml` | Model name to `auto`, tool filtering per client shape, the question lifted out of the envelope |
| `20-intake-route.yaml` | `/v1/messages` converted to chat completions, everything else passed through with the Host rewritten |

Edit before applying: the Service name `model-gateway.agentgateway-system.svc.cluster.local`
in `20-intake-route.yaml`, which is the gateway this hop forwards to.

These are the files as they run in
[the task routing lab](https://github.com/tjorourke/solo-labs/tree/main/agentgateway-inference-task-routing-eks),
where the hop sits in front of vLLM Semantic Router on a live cluster.
