# Running Cursor against agentgateway

Sample configuration for the how-to at
<https://mastertheagent.com/solo/agentgateway-cursor-setup/>.

`yaml/` is the Enterprise CRDs, `yaml-oss/` the same objects on the OSS CRDs, generated by the
group and kind swap the page describes.

```bash
kubectl apply -f yaml/       # or yaml-oss/
```

| File | What it is |
| --- | --- |
| `00-gateway.yaml` | A Gateway named `my-gateway`, HTTP listener, ClusterIP Service |
| `10-backend.yaml` | An ordinary AI backend, OpenAI chat completions |
| `20-route.yaml` | Everything under `/v1/` to that backend |
| `30-client-policy.yaml` | JWT verification, the tool filter that fixes Cursor's 503, and the branch that lifts the question out of the envelope |

Edit before applying: the model and host in `10-backend.yaml`, and the issuer, audience and
JWKS URL in `30-client-policy.yaml`.

The configuration here was validated as part of
[the prompt-aware model routing labs](https://github.com/tjorourke/solo-labs/tree/main/agentgateway-inference-task-routing-eks),
where the same policies run against real editors on a live cluster. These files are that
configuration reduced to one gateway, so they are a starting point rather than a lab you run
end to end.
